# Установка сервера на Ubuntu

Инсталлятор предназначен для отдельной чистой Ubuntu 24.04 LTS с доступом root.
Его нельзя запускать поверх существующей установки EchoWear: он проверяет
наличие каталогов `/etc/echowear` и `/var/lib/echowear` и отказывается их
перезаписывать. Существующий VPS этим проектом автоматически не изменяется.

Перед запуском направьте A-запись отдельного домена на сервер. TCP-порт 80
должен быть доступен извне и свободен для проверки Let's Encrypt; порт 18444
должен быть доступен колонке. Если создана AAAA-запись, IPv6 тоже должен вести
на этот сервер. Серверу нужен доступ к пакетным репозиториям Ubuntu, Docker Hub,
Go modules, PyPI, OpenAI API, Yandex Search API и к сайтам найденных картинок.
Для сборки нужны свободное место и оперативная память; на машине с малым объёмом
памяти может понадобиться swap.

Из корня клонированного проекта запустите:

```sh
sudo bash server/install/install.sh
```

Сценарий запросит домен, email для Let's Encrypt, идентификатор каталога Yandex
Cloud и два API-ключа. Пока поддерживается пояс `Asia/Yekaterinburg` (UTC+5).
Ключи вводятся без отображения в терминале; домен и идентификатор каталога
сохраняются отдельно от них. Затем сценарий установит пакеты Docker, Docker
Compose, certbot и OpenSSL из Ubuntu, получит сертификат и соберёт четыре
контейнера из исходников. Сценарий не меняет правила сетевого экрана.
После запуска он проверяет состояние всех четырёх контейнеров и обращается к
шлюзу через TLS на loopback, проверяя сертификат и ответ OTA. Если проверка не
прошла, установка не объявляется успешной.

Команда для вывода OTA-адреса после установки:

```sh
sudo bash server/install/show-ota.sh
```

Полученный адрес надо установить в колонке. Сам сервер прошивку не обновляет.
API-ключи и токены хранятся в `/etc/echowear`, данные — в `/var/lib/echowear`.
Docker credentials передаются в контейнеры через файлы, а не аргументами
команды или в репозитории. Голосовой сервис опубликован только на loopback;
наружу слушает только TLS-шлюз. Общие Docker-журналы контейнеров отключены.
Ограниченный технический журнал прослушивания можно включить командой
`sudo touch /var/lib/echowear/data/voice-events-enabled`. Журнал хранится как
`/var/lib/echowear/data/voice-events.log` с ограничением размера и не содержит
аудио или текста фраз. Чтобы выключить запись, удалите файл-маркер.

Certbot настраивает автоматическое продление сертификата, deploy-hook
перезапускает шлюз. Для HTTP-проверки порт 80 должен оставаться свободным и
доступным при продлении. Проверить состояние после установки:

```sh
sudo docker compose --env-file /etc/echowear/config.env -f server/install/compose.yaml ps
sudo systemctl status certbot.timer
```

Если после создания файлов установка прервалась, сценарий специально не
стирает их и не перезаписывает при повторном запуске. После устранения ошибки
запустите восстановление, которое проверяет маркер установки, файлы,
сертификат и принадлежность контейнеров перед продолжением:

```sh
sudo bash server/install/recover.sh
```

Если DNS работает на хосте, но не внутри Docker build, предусмотрен отдельный
вариант сетевого режима только для сборки:

```sh
sudo docker compose --env-file /etc/echowear/config.env -f server/install/compose.yaml -f server/install/compose.build-host.yaml build
sudo docker compose --env-file /etc/echowear/config.env -f server/install/compose.yaml up -d
```

Если сбой произошёл до записи маркера или создания одного из обязательных
файлов, восстановление остановится и попросит ручную диагностику; оно не
удаляет данные и не создаёт ключи заново. Проверьте `certbot.timer` после
восстановления. Если новый сертификат не применяется, проверьте код завершения
certbot deploy-hook и состояние контейнера шлюза.

Текущие версии шлюза, voice и установленной прошивки ожидают UTC+5. Другие
часовые пояса пока не поддерживаются, а срабатывание будильника при переводе
часов на летнее время не проверено.

Проверки без настоящих ключей:

```sh
node --test server/gateway/gateway.test.js server/install/default-config.test.js
bash server/install/test-effective-config.sh
bash server/install/test-recover.sh
```

Вторая проверка запускает временный контейнер без сети и использует тестовый
ключ. Дополнительные проверки собранных образов — `test-voice-runtime.sh`,
`test-gateway-e2e.sh` и `test-image-runtime.sh`: они используют временные
сертификаты, фиктивные ключи и синтетические поставщики без сетевых запросов к
OpenAI или Яндексу. Для них нужны Docker-образы, собранные с проектом
`echowear-merge-test`; имена можно переопределить переменными, указанными в
сценариях. Проверка изображений требует root для создания тестовых UID сокетов.

Проверки не заменяют испытание получения и продления настоящего сертификата и
голосового диалога с реальными сервисами после развёртывания. Этот установщик
создаёт новую систему и не выполняет миграцию или удаление действующего VPS.
