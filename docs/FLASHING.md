# Прошивка EchoEar-2ST по USB

Готовые файлы: [GitHub Releases](https://github.com/AlexeySmirnov74/EchoEar-ChatGPT-YandexApi/releases).
Для версии `v0.2.0-experimental` скачайте и распакуйте **`echoear-2st-usb-update-v0.2.0-experimental.zip`**.
Репозиторий приватный: для скачивания нужен вход в GitHub с доступом к проекту.

## Для какой колонки подходит релиз

- EchoEar-2ST **без разъёма BaseBoard**, ESP32-S3, flash **16 MiB**, PSRAM **8 MiB**.
- Существующие исправные загрузчик, таблица разделов и заводские ресурсы дисплея версии 1.
- Secure Boot и Flash Encryption выключены. Если `esptool` сообщает о включённой защите или запрещает операцию, остановитесь; этот рецепт её не обходит.

На одном таком устройстве проверена загрузка **именно этого образа приложения**, использование сохранённого адреса сервера и сохранность настроек. Полная последовательность USB-команд ниже проверена по синтаксису, тестам и реальной резервной копии; её повторная запись на другом устройстве пока не подтверждена. Сохранение нового адреса через браузер после этой сборки ещё требует отдельной проверки пользователем.

Это **обновление существующей колонки**, а не полный образ для стёртого чипа. Оно сохраняет заводские анимации, загрузчик, Wi-Fi и настройки. Не выполняйте `erase-flash`. На другом EchoEar, варианте с BaseBoard, другой разметке или размере flash этот пакет применять нельзя.

## Что лежит в архиве

| Файл | Назначение |
| --- | --- |
| `echoear-2st-app.bin` | Приложение, записывается в `ota_0` по адресу `0x20000`, **не по адресу 0**. |
| `ota-data-initial.bin` | 8192 байта `0xFF`: сброс выбора OTA-раздела по адресу `0xD000`, чтобы загрузчик выбрал `ota_0`. Это не раздел пользовательских настроек. |
| `check_flash_backup.py` | Локальная проверка резервной копии, разметки, заводских ресурсов и точного результата записи; к USB сама не подключается. |
| `FLASHING.md`, `release.json`, `SHA256SUMS.txt` | Инструкция, происхождение сборки, ограничения проверки и SHA-256 файлов. |
| `licenses/` | Лицензии проекта и зависимостей сборки. |

В образе нет ключей OpenAI/Яндекса, Wi-Fi-паролей или адреса вашего VPS. Резервный OTA-адрес — неработающий `https://example.invalid/`; рабочую ссылку сохраняют через портал колонки. API-ключи остаются на сервере. Внутренняя версия ESP-IDF-приложения пока `2.0.5`; версия релиза проекта — `v0.2.0-experimental`. Контрольная сумма приложения:

## 1. Подготовить компьютер

Нужны Python 3.10 или новее, USB-кабель **с передачей данных** и стабильное питание. Закройте программы, которые заняли COM-порт. Все дальнейшие команды выполняются в распакованной папке архива.

### Windows / PowerShell

Найдите порт в «Диспетчер устройств → Порты (COM и LPT)». `COM6` ниже — пример, замените его своим.

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install "esptool>=5,<6"
$EchoPort = "COM6"
function ep {
    & .\.venv\Scripts\python.exe @args
    if ($LASTEXITCODE -ne 0) { throw "Команда завершилась с ошибкой; остановите прошивку." }
}
```

### Linux / Ubuntu

На Ubuntu при необходимости установите `python3-venv`. Выберите свой порт `/dev/ttyACM0` или `/dev/ttyUSB0`. Нужен доступ к нему; для пользователя Ubuntu обычно это членство в группе `dialout` с повторным входом в сеанс.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install 'esptool>=5,<6'
EchoPort=/dev/ttyACM0
ep() { .venv/bin/python "$@"; }
```

Остальные команды одинаковы для обоих вариантов. Они проверены с `esptool 5.6.0`. При любой ошибке остановитесь и разберитесь с ней, не продолжайте следующий шаг.

## 2. Проверить чип и сохранить две копии

Подключите и включите колонку. `esptool` переводит её в загрузчик через USB; экран в это время может погаснуть. Если порт не появился, сначала проверьте кабель и разъём. Для входа с BOOT используйте инструкцию именно вашей ревизии, если такая кнопка есть; кнопку питания не следует считать BOOT.

```sh
ep -m esptool --chip esp32s3 --port $EchoPort --after no-reset flash-id
ep -m esptool --chip esp32s3 --port $EchoPort --after no-reset get-security-info
```

Проверьте: обнаружен ESP32-S3, размер flash 16 MB, Secure Boot и Flash Encryption отключены. Затем прочитайте всю память дважды. Не перезапускайте приложение между чтениями — оно может изменить настройки.

```sh
ep -m esptool --chip esp32s3 --port $EchoPort --baud 460800 --after no-reset read-flash 0 0x1000000 backup-before.bin
ep -m esptool --chip esp32s3 --port $EchoPort --baud 460800 --after no-reset read-flash 0 0x1000000 backup-repeat.bin
ep check_flash_backup.py backup-before.bin --repeat backup-repeat.bin --app echoear-2st-app.bin
```

Оба файла должны иметь размер **16 777 216 байт**, а проверка должна вывести два сообщения `PASS`. Она проверяет полное совпадение копий, контрольную сумму и точную таблицу разделов, заголовок загрузчика, заводской архив ресурсов и SHA-256 приложения. Несовпадение означает остановку перед записью. При ошибках связи попробуйте `--baud 115200` во всех командах чтения/записи.

Резервную копию сохраните локально вне репозитория: в ней есть персональные настройки вашей колонки.

Ожидаемая разметка:

| Раздел | Начало | Размер |
| --- | --- | --- |
| `nvs` | `0x9000` | `0x4000` |
| `otadata` | `0xD000` | `0x2000` |
| `phy_init` | `0xF000` | `0x1000` |
| `ota_0` | `0x20000` | `0x3F0000` |
| `ota_1` | `0x410000` | `0x3F0000` |
| `assets` | `0x800000` | `0x800000` |

## 3. Записать приложение, сохранив ресурсы и настройки

Только после успешной проверки предыдущего шага:

```sh
ep -m esptool --chip esp32s3 --port $EchoPort --baud 460800 --after no-reset write-flash --flash-mode keep --flash-freq keep --flash-size keep 0x20000 echoear-2st-app.bin 0xD000 ota-data-initial.bin
```

`esptool` проверяет хэш записанных данных. Команда меняет только приложение `ota_0` и выбор OTA-раздела. `ota_1` сохраняется, но его содержимое зависит от истории вашей колонки; надёжный источник отката — полная проверенная копия. Ключ `--after no-reset` оставляет устройство в загрузчике до проверки.

До первого запуска прочитайте память ещё раз:

```sh
ep -m esptool --chip esp32s3 --port $EchoPort --baud 460800 --after no-reset read-flash 0 0x1000000 after-update.bin
ep check_flash_backup.py backup-before.bin --after after-update.bin --app echoear-2st-app.bin --ota-initial ota-data-initial.bin
```

Продолжайте только после `PASS: exact USB update verified...`. Это сравнение всего чипа: оно подтверждает, что загрузчик, таблица разделов, NVS, `ota_1` и заводские ресурсы не изменились. Если проверка не прошла, не перезагружайте колонку до диагностики или восстановления копии.

Перезапустить после успешной проверки можно командой чтения MAC-адреса с обычным сбросом:

```sh
ep -m esptool --chip esp32s3 --port $EchoPort --after hard-reset read-mac
```

Дождитесь загрузки экрана. Если колонка не включилась автоматически, включите её обычным удержанием кнопки питания.

## 4. Сохранить адрес своего сервера

1. Подготовьте VPS по [инструкции сервера](https://github.com/AlexeySmirnov74/EchoEar-ChatGPT-YandexApi/blob/v0.2.0-experimental/server/install/README.md). Его OTA-ссылку можно получить на сервере: `sudo bash server/install/show-ota.sh` из папки проекта.
2. Если колонка уже знает домашний Wi-Fi, на время запуска отключите для неё эту сеть. Через примерно минуту без соединения она перейдёт в настройку Wi-Fi. В коде также предусмотрен вход касанием во время старта до подключения к Wi-Fi; более длинное касание надёжнее очень быстрого.
3. Подключите ноутбук или телефон к точке `Xiaozhi-...`, которую показывает колонка, откройте **http://192.168.4.1**. Это веб-страница на ноутбуке/телефоне; вводить текст на экране колонки не нужно.
4. Во вкладке **«Дополнительно»** вставьте персональный HTTPS URL OTA своего сервера и нажмите **«Сохранить»**. Формат: `https://echo.example.com:18444/<ваш-токен>`.
5. На вкладке настройки Wi-Fi выберите домашнюю сеть и сохраните пароль. Верните доступ к домашней сети, если отключали его, и перезапустите колонку. Ноутбук после этого тоже подключите обратно к обычному Wi-Fi.
6. Проверьте голосовой ответ после одного касания, громкость, яркость, картинки, режим отдыха и будильник. WebSocket должен работать с тем же доменом и портом, что и OTA; без доступного собственного сервера разговор не заработает.

Если в настройках сохранилась рабочая ссылка вашего сервера, повторный ввод не нужен. Стандартные Wi-Fi-параметры сохраняются. Старую некорректную запись `ota_url` эта общая сборка автоматически не исправляет: в таком случае сохраните ссылку через портал заново.

## 5. Вернуться к своей прежней прошивке

Используйте полную копию **этой же колонки**, сохранённую перед обновлением. Запись возвращает приложения, настройки, OTA-выбор и ресурсы к моменту копирования. Если включена защита flash, остановитесь; приведённые команды не предназначены для защищённых устройств.

```sh
ep -m esptool --chip esp32s3 --port $EchoPort --baud 460800 --after no-reset write-flash --flash-mode keep --flash-freq keep --flash-size keep 0 backup-before.bin
ep -m esptool --chip esp32s3 --port $EchoPort --baud 460800 --after no-reset read-flash 0 0x1000000 after-restore.bin
ep check_flash_backup.py backup-before.bin --repeat after-restore.bin
ep -m esptool --chip esp32s3 --port $EchoPort --after hard-reset read-mac
```

Перезагружайте после успешного сравнения копии и восстановления. Сбои USB чаще всего требуют исправить кабель/порт и повторить операцию в загрузчике, а не стирать весь чип.

Синтаксис чтения, записи, сохранения параметров flash и особенности объединённых образов сверены с [официальной документацией esptool](https://docs.espressif.com/projects/esptool/en/latest/esp32s3/esptool/basic-commands.html). Проверочный скрипт не определяет ревизию проводки, не проверяет eFuse-защиту, реальный объём PSRAM, совместимость функций конкретного заводского bootloader и не заменяет проверку устройства. Образ не предназначен для автоматической раздачи сервером OTA в этой версии проекта.
